# Internacionalización de la Web (ES · EN · FR · PT)

Trazabilidad: HU-05 «Gestión de perfil y preferencias (Mi Cuenta)», CA-04 (la preferencia de idioma se persiste en Account). No existe una HU específica de internacionalización; la cobertura de traducción está **pendiente de asignación por el PO**.

## Qué es y qué no es

- Traducción **determinista** de la interfaz, empaquetada con la Web. No hay CMS, ni servicio de traducción, ni traducción automática en tiempo de ejecución.
- El idioma es una **preferencia de interfaz**. Las rutas no cambian (no existen `/es`, `/en`…).
- Los **valores de negocio no cambian**. Solo cambia cómo se leen: textos, separadores de miles, formato de fecha y hora.

## Idiomas

| Código | Nombre                                     | Formato `Intl` |
| ------ | ------------------------------------------ | -------------- |
| `es`   | Español (**por defecto** y último recurso) | `es-CO`        |
| `en`   | English                                    | `en-US`        |
| `fr`   | Français                                   | `fr-FR`        |
| `pt`   | Português (redacción de Brasil)            | `pt-BR`        |

La lista es cerrada, es la misma que acepta Account (`PreferredLanguage`) y está en `src/shared/i18n/languages.ts`.

## Arquitectura

```
src/shared/i18n/
  languages.ts               lista cerrada, endónimos, locale de Intl
  i18n.ts                    instancia de i18next; español empaquetado; en/fr/pt bajo demanda
  language.ts                store del idioma activo, espejo local, <html lang>, initLanguage()
  useAccountLanguageSync.ts  Account manda cuando hay sesión
  format.ts                  formatInteger / formatDecimal / formatTime / countLabel
  errors.ts                  describeFailure: código → estado HTTP → mensaje (solo en español)
  locales/<idioma>/<namespace>.json
  locales/<idioma>/index.ts  descubre los namespaces con import.meta.glob (no se edita)
```

- **Librería:** `i18next` + `react-i18next`. Los componentes usan `const { t } = useTranslation()` y claves con namespace explícito: `t('inventory:slots.weapon1')`.
- **Carga:** `es` va en el bundle inicial. `en`, `fr` y `pt` son **un chunk por idioma**, que solo descarga quien elige ese idioma.
- **Namespaces:** uno por área funcional. Añadir un JSON en las cuatro carpetas basta: `index.ts` lo descubre solo.

  | Namespace  | Cubre                                                                                    |
  | ---------- | ---------------------------------------------------------------------------------------- |
  | `common`   | acciones genéricas, sí/no, roles, estados, recuentos con plural, componentes compartidos |
  | `app`      | cabecera, navegación, sesión, créditos, rutas de acceso                                  |
  | `errors`   | descripciones por código estable y por estado HTTP                                       |
  | `auth`     | inicio de sesión, segundo factor y recuperación de acceso                                |
  | `account`  | registro (HU-01), Mi cuenta, estadísticas y logros, panel administrativo de usuarios     |
  | `commerce` | vitrina, filtros, detalle, carrito, carrito guardado y pago simulado                     |
  | `catalog`  | listado del catálogo y ficha canónica                                                    |
  | `reviews`  | comentarios, calificación y reportes de producto                                         |

- **Validaciones con `MESSAGES`:** `localizedMessages({ clave: 'ns:ruta' })` (`src/shared/i18n/messages.ts`) devuelve un objeto cuyas propiedades se traducen **al leerse**. Así `MESSAGES.required` sigue siendo un texto para las pruebas y la validación habla el idioma activo sin duplicar reglas.
- **Estado con avisos:** cuando un componente guarda un aviso en su estado, guarda la **clave** y la traduce al pintar; así el aviso cambia si el idioma cambia mientras está visible.

## Resolución del idioma

1. **Arranque** (`main.tsx` → `initLanguage()`, antes del primer render): usa el espejo local `nexus-battles.language` si es válido; si no, español. No se usa `navigator.language`, para que el español siga siendo la experiencia por defecto.
2. **Con sesión:** cuando llega `GET /accounts/me` (la misma consulta que ya hace la cabecera, sin petición extra), si `preferredLanguage` es `es`/`en`/`fr`/`pt`, **Account manda**: se aplica y se actualiza el espejo local. Si es `null` (nunca eligió), se respeta el idioma local.
3. **Mi cuenta → Preferencias → Idioma:** el cambio se aplica al instante (sin F5 ni cerrar sesión) y después se hace `PATCH /accounts/me { preferredLanguage }`. Si Account falla, se vuelve al idioma anterior y se avisa.
4. **Cerrar sesión** no borra el espejo local. Al iniciar sesión otra cuenta, su preferencia guardada toma el control.
5. **Clave que falta** en `en`/`fr`/`pt`: se muestra en español (`fallbackLng: 'es'`), nunca el identificador.

El **tema** (claro/oscuro) sigue siendo una preferencia local del navegador (`nexus-battles.theme`) y es independiente del idioma.

## Errores del servicio

`describeFailure(error, t, idioma)` nunca compara el texto del mensaje. Sigue este orden:

1. Código estable del servicio con traducción conocida (`errors:codes.<CÓDIGO>`).
2. **En español**, el mensaje del servicio tal cual, como hasta ahora.
3. **En otro idioma**, una descripción localizada según el estado HTTP (400, 401, 403, 404, 409, 422, 429, 5xx, red).

**Limitación conocida:** Account y Player-Inventory no envían códigos estables, así que en `en`/`fr`/`pt` sus errores se describen por estado HTTP, de forma genérica.

## Frontera de traducción

| Sí se traduce (interfaz)                                                                                                                                     | No se traduce (contenido y contratos)                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| navegación, títulos, botones, etiquetas, placeholders, estados vacíos y de carga, confirmaciones, diálogos, `aria-label`, `title`, `alt` de interfaz, toasts | nombres elegidos por usuarios (`displayName`), mensajes del chat                                                      |
| estados y tipos derivados de enums o códigos (`ACTIVE` → «Vigente», `ARMA` → «Arma»)                                                                         | nombres y descripciones de productos de Catalog (p. ej. «Daga de fuego»), nombres de héroes y habilidades persistidos |
| textos de batalla construidos por la Web a partir de códigos                                                                                                 | contenido de misiones, subastas y reseñas                                                                             |
|                                                                                                                                                              | UUID, SKU, IDs, subjects, rutas, claves de payload, códigos HTTP, enums internos                                      |

Casos límite decididos:

- **Etiquetas del esquema de atributos** (`kind`, `basePower`, `ALLY`, `INCREASE`…): son claves y códigos, se traducen (`commerce:attributes.*`). Un valor libre o un nombre que llegue dentro de los atributos se muestra tal cual.
- **Preguntas de seguridad y documentos legales del registro:** se traducen; al backend solo viaja el identificador de la pregunta.
- **Nombres de países:** `Intl.DisplayNames` del idioma activo; el valor guardado sigue siendo el código ISO.
- **Catálogo visual oficial** (`shared/visual-library/products/product-catalog.ts`): son los 72 nombres oficiales transcritos de EN-026.1; es contenido y no se traduce.
- **Nombres de logros y reconocimientos** (Missions): contenido, no se traducen; su estado de entrega sí.
- **Errores internos de guarda** (`throw new Error('No hay un carrito…')`) no se traducen en origen: `describeFailure` los muestra tal cual en español y como fallo genérico en los demás idiomas.

## Plurales

Se usan los sufijos de i18next (`_one`, `_many`, `_other`), resueltos con `Intl.PluralRules`. Nunca se escriben condicionales por idioma. En `fr` y `pt`, `0` usa la forma singular. En `es`, `fr` y `pt` existe `many` («1.000.000 de créditos»). La cifra se pasa ya formateada: `countLabel(t, 'common:count.credits', n)`.

## Pruebas

- `completeness.test.ts`:
  - mismos namespaces en los cuatro idiomas;
  - mismas claves y mismas variables de interpolación que en español;
  - ningún texto vacío;
  - categorías de plural completas por idioma;
  - **toda clave `namespace:clave` escrita en el código existe en español**.
- `i18n.test.ts`: cambio de idioma, `<html lang>`, espejo local, recarga, fallback, interpolación, plurales (0, 1, 2 y un millón), formato por locale, créditos compactos, errores.
- `useAccountLanguageSync.test.tsx`: Account manda; `null` conserva el local; una lectura vieja no revierte un cambio nuevo; cambio de cuenta.

## Cómo añadir un texto

1. Añadir la clave en `locales/es/<ns>.json` y su traducción en `en`, `fr` y `pt` (las pruebas fallan si falta alguna).
2. Usarla en el componente: `t('<ns>:<clave>')`.
3. Sin concatenar frases: `t('ns:clave', { nombre })`, nunca `'Hola ' + nombre`.
